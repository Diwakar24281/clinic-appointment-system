Phase 1: Problem Discovery

Problem Statement & Real-World Inefficiencies

Analytical breakdown of core failure points documented in our Capstone Runbook.

Operational Deficiencies
! Double-Booking Collisions & Concurrency Races

When appointment booking relies on phone calls, manual counter walk-ins, or un-synchronized forms, receptionists frequently assign the exact same physician time slot to multiple patients.

  • Severe scheduling overlaps and doctor schedule disruption
  • Zero database-enforced unique constraints on time slots
  • Race conditions during simultaneous web bookings
! Opaque Physical Waiting Queue Management

Patients in the waiting area have no insight into the consultation progress, leading to frequent interruptions at reception and chaotic room crowding.

  • Zero real-time synchronization between doctor room and lobby
  • No doctor-isolated sequential token allocation mechanism
  • Excessive waiting times averaging 90+ minutes
! Illegible & Ephemeral Paper Prescriptions

Handwritten medical notes lead to pharmacy dispensing errors, lack persistent centralized archival, and cannot be digitally retrieved by patients.

  • Lost medication logs and historical diagnoses
  • Zero standardization for dosage, frequency, and duration
! Lack of Centralized Administrative Auditing

Clinic owners have no real-time metrics on doctor availability, daily revenue collection, completed vs cancelled visits, or weekly utilization trends.

  • Manual end-of-day tallying prone to discrepancies
  • Inability to dynamically update doctor weekly rosters

Phase 3: Backend Engine

Java Backend Engine & Controller / Service / DAO Architecture

Strict separation of concerns implemented with Spring Boot 3 enterprise patterns.

Spring Boot 3
AppointmentService.java (Concurrency Lock) 
@Transactional
public AppointmentResponse bookAppointment(AppointmentRequest req) {
    // 1. Prevent Double-Booking Collision at Service Layer
    boolean exists = appointmentRepo.existsByDoctorIdAndAppointmentDateAndAppointmentTime(
        req.getDoctorId(), req.getAppointmentDate(), req.getSlotTime()
    );
    if (exists) {
        throw new ResponseStatusException(HttpStatus.CONFLICT, "Slot already booked");
    }
    // 2. Compute Doctor-Date Isolated Sequential Token Number
    Integer maxToken = appointmentRepo.findMaxTokenNumber(req.getDoctorId(), req.getAppointmentDate());
    int nextToken = (maxToken == null) ? 1 : maxToken + 1;

    Appointment appt = new Appointment(..., nextToken, Status.BOOKED);
    return new AppointmentResponse(appointmentRepo.save(appt));
}

Phase 4: Runbook Bug Log

Systematic Bug Diagnosis & Resolution Log (BUG-01 to BUG-04)

Engineering challenges diagnosed and resolved during our Capstone implementation.

4 Critical Fixes
Bug ID Symptom / Error Root Cause Identified Code Fix Applied Status
BUG-01 CORS blocked API requests when accessing frontend on port 5500. Spring Boot backend on port 8080 lacked Access-Control-Allow-Origin. Added @CrossOrigin(origins = "*") and served static bundle on port 8080. RESOLVED
BUG-02 Race condition on simultaneous booking for identical slot. Microsecond gap between JPA availability check and save(). Added DB composite UNIQUE constraint on (doctor_id, date, slot_time) & 409 mapping. RESOLVED
BUG-03 Infinite JSON recursion / StackOverflowError on Prescriptions. Bidirectional JPA @OneToMany / @ManyToOne Jackson loop. Decoupled entities from API with DTO records (PrescriptionResponse). RESOLVED
BUG-04 Appointment date shifted backwards by 1 day due to UTC offset. Using legacy java.util.Date with timezone serialization mismatch. Refactored to ISO java.time.LocalDate & LocalTime with explicit formatting. RESOLVED
